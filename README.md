# coldbase

**Кратко:** загрузка холодной базы из Excel в **AmoCRM** или **Bitrix24** (две вкладки): проверка контактов по выбранному полю, исключение дублей, создание сущностей в CRM с маппингом полей и выбором воронки/стадии. Для Amo — OAuth; для Bitrix — входящий вебхук `B24_WEBHOOK_URL`. Защита паролем, Docker.

Загрузка холодной базы из Excel в AmoCRM: проверка контактов в AmoCRM по выбранному полю (идентификатору), список исключений и создание лидов из остальных записей с настраиваемым маппингом и выбором воронки.

## Сборка и запуск

```powershell
cd D:\coldbase
npm install
npm run build
npm start
```

Режим разработки: `npm run dev`.

## Docker (деплой)

На сервере создайте `.env` (см. `.env.example`), затем:

```powershell
docker compose up -d --build
```

Приложение будет на порту 3000. Токен AmoCRM сохраняется в папке `./data` на хосте (volume). Для продакшена задайте в `.env`:

- `AMOCRM_REDIRECT_URI=https://ваш-домен/api/amo/callback`

Перезапуск: `docker compose up -d --build`. Остановка: `docker compose down`.

## Настройка AmoCRM

1. Создайте интеграцию в кабинете AmoCRM (client_id, client_secret, redirect_uri).
2. **Redirect URI** в настройках интеграции укажите тот же URL, что и в `.env` (например для продакшена: `https://ваш-домен/api/amo/callback`).
3. Скопируйте `.env.example` в `.env` и заполните переменные (в т.ч. `AMOCRM_REDIRECT_URI` для вашего окружения).
4. В браузере откройте приложение и перейдите по ссылке «Авторизация AmoCRM» — после входа токен сохранится в `data/amocrm-token.json`.

### Ошибка «Cannot decrypt the authorization code» (400)

Означает недействительный токен или несовпадение настроек OAuth. Сделайте:

1. **Проверьте .env:** `AMOCRM_REDIRECT_URI` должен **дословно** совпадать с Redirect URI в настройках интеграции AmoCRM (включая `http`/`https`, хост и путь). Для локального запуска — `http://localhost:3000/api/amo/callback` (без завершающего слэша, если в кабинете указано так же).
2. **Проверьте `AMOCRM_CLIENT_SECRET`** — без лишних пробелов, скопирован из кабинета интеграции.
3. Удалите сохранённый токен: файл `data/amocrm-token.json` (или папку `data`).
4. Запустите приложение снова и заново нажмите «Авторизация AmoCRM» в настройках, войдите в AmoCRM и дождитесь редиректа на приложение.

После этого повторите «Проверить в AmoCRM».

## Настройка Bitrix24

1. Создайте **входящий вебхук** с правами на CRM (сделки, контакты).
2. В `.env` укажите `B24_WEBHOOK_URL` (полный URL вида `https://портал.bitrix24.ru/rest/USER/SECRET/`).
3. Откройте вкладку **Bitrix24**: загрузка Excel и сценарий такие же, как у Amo — проверка дублей контактов (`crm.duplicate.findbycomm`), затем создание **контакта + сделки** в выбранной воронке и стадии (по умолчанию подставляются воронка «Холодный прозвон» и стадия «Холодная база», если они есть в портале).

## Использование

1. Загрузите Excel-файл с холодной базой (вкладка AmoCRM или Bitrix24).
2. Выберите колонки-идентификаторы (телефон/email) и нажмите «Проверить в AmoCRM» или «Проверить в Bitrix24».
3. Просмотрите списки «Исключения» и «К добавлению».
4. Нажмите «Загрузить воронки и поля…», выберите воронку и при необходимости статус/стадию, настройте маппинг колонок Excel → поля лида (Amo) или сделки (Bitrix).
5. Нажмите «Загрузить в CRM».
